AI Assistant Module

PROJECT

Python · AI Integration

[SHIPPED]
» » »∆

An AI assistant built directly into an existing business system. It reads incoming data, highlights important trends and automates routine decisions.

The constraint that shaped this one was that nothing could be rebuilt. The business already had its system, its data and its habits, so the assistant had to live inside that — reading from the same tables the staff were already filling in, and surfacing its output where they were already looking instead of in a separate tool nobody would open.

It watches incoming records, compares them against recent history and flags the movements worth a human glance: an unusual spike, a figure drifting away from its normal range, a record that contradicts the others. The routine decisions it does take on are the mechanical ones — categorising, routing, filling in what can be inferred — and every one of them stays visible and reversible.

  • Reads the host system's own data, no parallel database
  • Trend and anomaly flagging on incoming records
  • Automated routine decisions, logged and reversible

Smart Survey System

PROJECT

Python · Full-Stack

[SHIPPED]
» » »∆

An adaptive survey engine. Rule-based logic changes the follow-up questions in real time based on each respondent's previous answers.

A fixed questionnaire asks everyone the same thing and wastes most of it. This one treats the survey as a graph instead of a list: each answer opens the branches that are now relevant and closes the ones that no longer apply, so a respondent only ever sees questions that make sense given what they have already said.

The branching lives in data, not in code. Conditions are stored alongside the questions, which means the person running the survey can change the logic without a deploy, and the answers still land in a clean relational shape — one row per response, with the path taken recorded — so the results stay analysable rather than turning into a pile of sparse columns.

  • Conditional branching evaluated per answer, in real time
  • Rules stored as data so non-developers can edit them
  • Normalised response storage built for later analysis

Car Dealer Catalog

PROJECT

Web · Database

[SHIPPED]
» » »∆

A digital showroom for car dealers. It organizes a large vehicle inventory and gives buyers clear, structured details for every car on sale.

Dealer inventory is messy by nature: the same model arrives in different trims, years, colours and conditions, and the listings are usually typed by whoever happened to take the car in. The fix was a proper catalog model — make, model, variant, year and condition as real fields rather than free text — so that filtering actually works and two listings for the same car look like the same car.

On the buyer's side that turns into a page that answers the obvious questions without a phone call: specification, mileage, condition and photographs laid out the same way for every vehicle. On the dealer's side it turns into one place to add, update and retire a listing, with the stock count staying correct instead of drifting out of date.

  • Structured vehicle schema instead of free-text listings
  • Filterable catalog across a large, mixed inventory
  • Consistent detail page for every car on sale
